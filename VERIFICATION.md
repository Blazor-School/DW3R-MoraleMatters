## 1.1.0 reinforcement morale and native reward reconciliation

### Native investigation

- The supported executable SHA-256 still matches `b57a2d4cbd01c9c5abd651fa42f43a4b8fdae88da6403106cd5f5c1bf4dade70`.

### Implemented behavior

- Defaults: Reinforcements.Enabled=1, MoralePerTenPercent=10, WaveMoraleCap=50, WaveSeconds=3. Gain/cap accept 0-898; the quiet window accepts 0.25-10 battle seconds.
- A previously reserved native reinforcement group can qualify only once per battle. Existing groups, dead-group reactivation, healing, actor visibility and ordinary corps/side transfers do not generate arrivals. Entirely new corps with zero soldiers before the wave get no additional starting morale.
- Soldiers exclude each group's leader. Groups arriving within the quiet window share the pre-wave soldier denominator and one cap. Native activation must complete before the reward; stuck requests expire after 30 battle seconds without reward.
- Target is min(cap, gain-per-ten-percent * 10 * arriving / previous). The missing portion is added permanently to native base morale, preserving the support bonus ledger, expiry, event/casualty changes and 899 ceiling.
- Recent positive native changes and positive native changes during the wave count toward the target. This attribution is deliberately conservative: unrelated native gains nearby in battle time may reduce the top-up. Linked scenario-event credit is additionally retained beyond the quiet window, without double-counting the same native gain in both ledgers. Late same-event native awards replace previously paid mod gains, limited to that wave's remaining paid amount. Larger native rewards are retained. Multiple event keys can share one capped wave; one event can span several waves.
- The no-wave path does no additional group scan. Open waves scan validated native formation storage; this avoids introducing reflected character walks or per-group VirtualQuery calls into the normal polling path.
